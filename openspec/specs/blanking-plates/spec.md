# blanking-plates Specification

## Purpose

Let a user cap leftover Gridfinity grid in a drawer with a thin, wall-less plate generated by the same CLI
that produces the bins, so a finished drawer has no exposed baseplate lattice.

A blanking plate is distinct from the two similarly named things it sits between: a **baseplate** is the
grid lining the drawer, and a **base** is a bin's own footed bottom. A **blanking plate** is a base used on
its own, with no bin built on top of it.

## Requirements

### Requirement: Wall-less blanking plate at base height

The system SHALL generate a blanking plate consisting of a Gridfinity base and nothing else: no walls, no
pocket, no cutouts, no dividers and no stacking lip. Its height SHALL be the height of one Gridfinity base
as built by the pinned `gridfinity_build123d`, and SHALL NOT be configurable.

#### Scenario: Generate a blanking plate

- **WHEN** a user requests a blanking plate for a given grid size
- **THEN** the system produces a part one Gridfinity base tall, with no walls and no pocket

#### Scenario: Plate carries no material above the base

- **WHEN** a blanking plate is generated
- **THEN** no material exists above the top of the Gridfinity base, which is what distinguishes it from a bin

#### Scenario: Blanking plate is a valid solid

- **WHEN** a blanking plate is generated
- **THEN** the resulting part is a valid, watertight solid suitable for export

### Requirement: Plate footprint matches the equivalent bin

The system SHALL give a blanking plate the same footprint as a bin of the same grid size, so the plate drops
into the same baseplate cells. Grid dimensions SHALL be validated over the same supported range as bins, with
an actionable error naming the invalid parameter.

#### Scenario: Footprint matches a bin of the same grid

- **WHEN** a blanking plate and a bin are generated with the same `grid_x` and `grid_y`
- **THEN** their X and Y bounding-box dimensions are identical

#### Scenario: Reject an out-of-range grid size

- **WHEN** a user requests a blanking plate with a grid dimension outside the supported range
- **THEN** the system refuses generation and reports which parameter is invalid

### Requirement: Bin-only options do not alter a blanking plate

The system SHALL leave a blanking plate unchanged when bin-only options are supplied, including pocket
dimensions, cutouts, dividers, the stacking lip and the height flags, and SHALL document in the CLI help
that they do not apply, so a user is not left believing a flag took effect.

#### Scenario: Bin-only flags leave the plate unchanged

- **WHEN** a user requests a blanking plate and also passes bin-only options such as pocket, cutout or
  divider flags
- **THEN** the generated plate is identical to one generated without them

#### Scenario: Height flags do not resize the plate

- **WHEN** a user requests a blanking plate and also passes a height flag
- **THEN** the plate is still one Gridfinity base tall

### Requirement: Blanking plates use the existing export and print-bed paths

The system SHALL export a blanking plate through the same path as any other model, SHALL give it a
deterministic default filename in the established style, and SHALL check it against the configured print
volume using its actual bounding box.

#### Scenario: Export a blanking plate

- **WHEN** a user exports a blanking plate to a supported format
- **THEN** the system writes a valid file for that format

#### Scenario: Deterministic default filename

- **WHEN** a user requests a blanking plate and omits the output path
- **THEN** the system uses a deterministic filename identifying it as a blanking plate and naming its grid

#### Scenario: Print-bed check applies to a blanking plate

- **WHEN** a blanking plate's footprint exceeds the configured print volume
- **THEN** the system warns which axis is exceeded and by how much, then continues to export

### Requirement: Adding blanking plates leaves bins unchanged

Introducing blanking plates SHALL NOT change the geometry, parameters or validation of any existing bin.

#### Scenario: Existing bin geometry is unchanged

- **WHEN** a bin is generated with the same parameters as before this capability existed
- **THEN** the resulting geometry is identical
