## Why

A drawer lined with a Gridfinity baseplate is rarely filled exactly by bins. Whatever grid is left over sits
exposed: an open lattice that catches crumbs, looks unfinished, and lets small items slide underneath. The
fix is a thin flat cap that occupies the leftover grid and nothing more.

Terminology matters here, because three similar words mean different things in this project:

- A **baseplate** is the grid that lines the drawer.
- A **base** is a bin's own footed bottom, the part that mates with the baseplate.
- A **blanking plate** is what this change adds: a wall-less base, used on its own to cap exposed grid.

Today a blanking plate cannot be built at all. `BinParameters.validate()` requires an effective height
strictly greater than 7 mm, and `KitchenBin` always extrudes walls around a pocket. Bins of 7 mm and above
already serve the "solid filler" case through `--no-cutouts`, so the missing piece is specifically the thin,
wall-less one at base height.

## Epic

Let a user cap any leftover Gridfinity grid in a drawer with a thin, flat, wall-less plate generated by the
same CLI that produces the bins, so a finished drawer has no exposed lattice.

## User Stories

- As someone organising a kitchen drawer, I want to generate a flat plate that fills leftover grid, so that
  the drawer has no exposed baseplate lattice for crumbs and small items to fall into.
- As someone printing a set of bins, I want the blanking plate to come from the same CLI with the same grid
  arguments, so that I do not have to learn a second tool or hand-edit a model to fill a gap.
- As someone remixing the models, I want the plate to be honestly the minimum geometry required, so that it
  prints quickly and does not waste filament on a solid block.

## Acceptance Criteria

- Given a grid size, when a user requests a blanking plate, then the system produces a part exactly one
  Gridfinity base tall (7.804 mm as the pinned library builds it) with no walls and no pocket.
- Given a blanking plate request, when the part is generated, then its footprint matches the equivalent bin
  footprint for that grid, so it drops into the same baseplate cells.
- Given a blanking plate request, when the user also passes bin-only options such as pocket, cutout, divider
  or stacking-lip flags, then those options are rejected or ignored explicitly rather than silently altering
  the plate.
- Given a blanking plate, when it is exported, then STL and 3MF both work through the existing export path.
- Given a blanking plate, when it is checked against the print bed, then its actual bounding box is measured
  like any other model.
- Given an existing bin invocation, when this change lands, then the generated bin geometry is unchanged.

## Non-goals

- **No stacking lip.** A drawer filler never has anything stacked on it. This is settled, not deferred.
- **No walls, pocket, cutouts or dividers at any height.** A plate that grows walls is just a bin, which
  already exists.
- **No baseplate generation.** The grid that lines the drawer is a separate object and stays out of scope;
  use `gridfinity_build123d` directly for that.
- **No multi-height plates.** A plate is one base tall. A taller solid filler is an existing bin with
  `--no-cutouts`.
- **No changes to bin geometry**, including the `> 7 mm` height floor as it applies to bins.

## What Changes

- Add a blanking plate as a distinct product with its own small parameter type, built from
  `gridfinity_build123d.BaseEqual` alone with no `Bin` wrapper, following the precedent set by the knife
  blade block rather than overloading `BinParameters`.
- Add a `--blanking-plate` CLI flag, mirroring how `--knife-block` selects a different product, with
  `--grid-x` and `--grid-y` applying to the plate's footprint.
- Give the plate a deterministic default output filename in the existing style.
- Route the plate through the existing export and print-bed paths unchanged.

## Capabilities

### New Capabilities

- `blanking-plates`: A thin, wall-less Gridfinity plate used to cap exposed grid, its fixed one-base height,
  its footprint, the rejection of bin-only options, and its export and print-bed behaviour.

### Modified Capabilities

None. The `> 7 mm` height floor lives only in `cutlery_bin.py`, not in any published requirement, so
relaxing or bypassing it changes no stated behaviour:

- `gridfinity-utensil-bin` keeps every requirement. Its validation requirement covers "height" generically
  and continues to hold for bins, whose behaviour is untouched.
- `multi-format-export` already requires export to apply to all bin types, which the plate satisfies without
  a requirement change.
- `print-bed-validation` already measures the model's actual bounding box.

## Test Strategy

- Unit tests for the new parameter type's validation, including rejection of an out-of-range grid.
- Real-geometry tests, auto-marked slow via the existing fixture convention, asserting the plate's height is
  one base tall, that its footprint matches the equivalent bin, and that it is a valid solid.
- A test asserting the plate has no material above the base, which is what distinguishes it from a bin.
- CLI tests using the existing mocked-factory convention, covering `--blanking-plate`, the default filename,
  and the handling of bin-only flags.
- A regression check that an existing bin regenerates byte for byte, mirroring the approach used for the
  stacking lip.
- Every scenario claimed by a `@pytest.mark.scenario("blanking-plates", ...)` marker so the traceability
  guard passes.

## Impact

- **`cutlery_bin.py`**: new `BlankingPlateParameters` dataclass and `create_blanking_plate()` factory. No
  change to `BinParameters`, `KitchenBin` or `CutleryBin`.
- **`main.py`**: new `--blanking-plate` flag, a branch in the build path, and a filename rule.
- **Dependencies**: none added. Uses `BaseEqual` from the already-pinned `gridfinity_build123d`.
- **Licensing**: no change. The plate is our own trivial composition of the library's base, so it is an
  original model under the project's existing CC BY-SA 4.0 choice for generated models.
- **Docs**: `README.md` and `CLAUDE.md` gain the flag and the terminology note, since baseplate, base and
  blanking plate are easy to confuse.
